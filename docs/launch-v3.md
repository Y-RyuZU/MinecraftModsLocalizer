## 45秒チュートリアルの台本

| 時間 | 画面と説明 |
| --- | --- |
| 0–5秒 | 「英語のクエストを日本語で読もう」。OS/CPUに合うダウンロードを示す。 |
| 5–13秒 | 設定画面でプロバイダー・モデル・APIキー入力位置と保存ボタンを示す。キーは空欄のまま撮影し、API料金が別に発生することを字幕にする。 |
| 13–22秒 | `mods`と`config`のあるゲームフォルダを選択。個人名を含まないテスト用のパスを使う。 |
| 22–30秒 | クエストを1つ選び、翻訳前の確認画面で通常API／Batchを選択して開始。実測より速い処理に見せる場合は「早送り」と明示。 |
| 30–40秒 | 完了画面の反映案内を確認し、Minecraftで同じクエストを開く。 |
| 40–45秒 | 同じクエストの翻訳前後を見せる。初回翻訳ガイドへのリンクで締める。 |

文章チュートリアルとゲーム内Before/After画像は用意済み。動画は未制作です。過去の実翻訳・適用成功とユーザー提供のゲーム画像を確認しています。

## Xでの見せ方とリンク配置

2026年10月1日確認。[Xの公開実装](https://github.com/xai-org/x-algorithm)は、閲覧者ごとの反応確率などを予測して順位を決めると説明している。公開された重みを、そのまま「返信1件で何倍伸びる」という計算には使えない。[公式ヘルプ](https://help.x.com/en/rules-and-policies/recommendations)も関心や交流など複数の情報を挙げている。

**今回の編集方針：本投稿は用途・効果・主な更新点と画像、最初の返信はダウンロードと導入ガイド。** これは試す構成であって、外部URLを返信に移せば必ず推薦が増えるという保証ではない。返信まで開く手間も増えるため、プロフィールのリンクも導入ページへ揃える案を用意する。設定変更は承認後に行う。

本投稿だけを読んでも何のツールか分かるようにする。「詳細は返信」だけで内容を隠さない。ハッシュタグはまず関連する1つ程度に絞り、画像の説明や用途に文字数を使う。これは読みやすさの判断で、アルゴリズムの固定ルールではない。

公開後は表示回数だけでなくリンククリック、ダウンロード、初回成功の報告を確認する。別日の投稿を比較しても内容・曜日・フォロワーの違いがあるため、リンク位置だけの効果とは断定しない。

## YouTube紹介チャンネルへの連絡案

検討する価値がある。最初は3〜5件、登録者数よりも視聴者との相性で選ぶ。候補は、クエスト型Modpackの攻略、海外Modの日本語紹介、導入方法の解説を最近扱っているチャンネル。直近の動画を見て、その人の動画でどのように役立つかを1文で説明できる相手に絞る。

最初の連絡は「紹介してください」だけではなく、試せる題材を添える。正式候補が安定した段階で、公開されている仕事用窓口へ個別に送る。公開前に使ってもらう場合は、候補版であること・既知の制限・公開予定を明示する。

用意するもの：

- 導入ガイドと、確認済みの対応Minecraft／Modpack版。
- そのチャンネルが扱う題材に近い、実際の翻訳前後画像と短い操作動画。
- どこまで動作確認したか、何が未対応か、API料金が必要なこと。
- 撮影に使える自作の説明画像とその利用条件。第三者Modのロゴやゲーム素材まで自由利用を約束しない。
- 不具合時の連絡先。試用や紹介、好意的な評価を条件にしない。

連絡文のひな形（相手の動画を確認してから空欄を埋める）：

紹介後に問い合わせが来ても初回翻訳まで案内できる状態を先に整える。候補者の選定や個別文案は準備可能だが、この文書だけでは送信の承認としない。現在、連絡・投稿は行っていない。

## 公開の順序

1. 必須条件を満たしたコミット・テスト結果・成果物一覧・Release本文をメンテナーへ提示する。
2. 明示承認後にpushとタグ作成を行い、ドラフトReleaseのCPU・署名・checksum・リンクを再確認する。
3. Release公開後、未ログイン状態でダウンロードとガイドを確認する。READMEの「v3開発中」の案内を公開済みの内容へ更新する。
4. 別途承認された日本語投稿を公開する。英語投稿も内容と投稿先の承認後に公開する。
5. 翌日と1週間後に、ダウンロード数・問い合わせ・初回成功の報告を手動で確認する。予約投稿や自動監視は設定していない。

## 初回成功を確かめる

初回利用者に「ダウンロード→起動→キー設定→1つ翻訳→ゲーム内で確認」を説明なしで試してもらい、失敗した段階と経過時間を記録します。最初の5人で試し、ゲーム内確認まで到達しなかった原因を優先して修正します。この人数は小規模の受入確認案で、統計的な成功率の証明ではありません。

記録欄：OS/CPU、アプリ版、Modpack版、使ったガイド言語、完了した段階、つまずいた操作、解決方法。キーや翻訳本文は集めません。ダウンロード数は成功人数として扱いません。テレメトリーは追加していません。
